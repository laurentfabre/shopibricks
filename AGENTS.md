# ShopiBricks

Databricks demo with separate FEVM and emerging-hackathon deployments. Always pass the profile explicitly selected by the user (`fevm` or `emerging-hackathon`); never infer it from CLI defaults. The hackathon deployment uses the `openai` catalog. Use Databricks core and product skills. Use MCP for SQL when available; native SDK/CLI OAuth for resources without MCP coverage. Never print or manually handle API tokens.

App developer owns `app/`; platform work owns `data/`, `resources/`, `scripts/`, `docs/` and the root bundle. Keep synthetic-data labels, real integration statuses and human checkout confirmation. Test meaningful state transitions and hosted behavior. Do not charge payments or enable continuous schedules without a bounded demo window.
